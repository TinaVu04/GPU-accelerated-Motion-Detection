# CUDA-Accelerated Motion Detection Using Customized CUDA Kernels
Team Member: Tina Vu

## Project Details
The project focuses on systems-level GPU optimization, CUDA kernel design, and device memory management. Video preprocessing is handled using OpenCV on the CPU, while stages 2 through 4 of the pipeline: Gaussian blur, frame differencing, and binary thresholding are implemented directly in CUDA. The pipeline is structured as a multi-file CUDA/Python system that separates kernel logic, pipeline orchestration, and application code into distinct files for clarity. A key architectural decision is the use of shared device buffers across pipeline stages, which avoids the 4–6 ms of PCIe transfer overhead that a naïve stage-independent implementation would incur per frame. The project is motivated by privacy concerns around cloud-connected home security cameras, demonstrating that effective real-time motion detection is achievable entirely on local GPU hardware without transmitting raw video off-device. Due to hardware constraints, no webcam on the GPU machine and no CUDA support on the development laptop, all GPU benchmarks were conducted using synthetic 1920×1080 frames generated by NumPy.

Resources:
- CUDA Toolkit 11.x / 12.x
- OpenCV-contrib (cv2.cuda module for GPU baseline comparison)
- Python 3.8+ with NumPy, SciPy, ctypes
- C/C++ compiler (gcc, nvcc)
- CHPC computing resources (NVIDIA GeForce GTX 1080)

Compute Requirements:
- CUDA-capable NVIDIA GPU 
- No webcam required since pipeline benchmarked using synthetic frames
- Development machine: Intel-based HP laptop (CPU baseline only)

# Custom CUDA Motion Detection — Setup & Execution

## Prerequisites

### 1. Verify GPU and CUDA
Run on the CHPC / lab machine:
```bash
nvidia-smi
nvcc --version
```
Expected: NVIDIA GeForce GTX 1080, CUDA 13.0

If nvcc is not found:
```bash
module load cuda
```

### 2. Install Python Dependencies
```bash
pip install numpy scipy opencv-contrib-python
```

> Must use opencv-contrib-python — the standard opencv-python
> does not include the cv2.cuda module needed for benchmarking.

## Step 1 — Build the Custom CUDA Kernels

This compiles the three CUDA kernel files and pipeline into a shared
library that Python loads via ctypes.

```bash
nvcc -O2 -arch=sm_61 --shared -Xcompiler -fPIC \
     -o pipeline.so          \
     pipeline.cu             \
     kernels/gaussian_blur.cu \
     kernels/frame_diff.cu   \
     kernels/threshold.cu
```

> -arch=sm_61 is required for the GTX 1080 (Pascal architecture).
> Do not change this flag or the kernels will not be optimized
> for this GPU.

Verify the build:
```bash
python3 -c "import ctypes; ctypes.CDLL('./pipeline.so'); print('pipeline.so loaded OK')"
```


## Outcomes:
- Functional motion detection pipeline with three custom GPU-accelerated CUDA kernels (gaussian_blur.cu, frame_diff.cu, threshold.cu)
- Multi-file project structure separating kernel math, pipeline orchestration, and application logic
- Three-way performance comparison: Intel CPU baseline vs OpenCV GPU vs custom CUDA pipeline
- Timing breakdown using CUDA events and accounting for multiple benchmark environments
- Technical writeup documenting kernel design, shared memory tiling, constant memory usage, warp divergence, and cross-stage memory sharing
